---
title: "Mismatch"
date: 2026-05-02
---
Vulnerabilities rarely live in bad code. They live in the space between two systems trying to talk to each other.

When developers build to a standard, they make micro-decisions about edge cases. Empty headers. Conflicting lengths. On its own, a system handles these just fine. The vulnerability appears when two systems sit back-to-back, holding different interpretations of the exact same rule.

Take James Kettle’s research on HTTP Request Smuggling. A frontend proxy and a backend server spoke the same protocol, but disagreed on where a request ended. It wasn't an application bug it was an infrastructure-level misunderstanding.

We see this everywhere today. API gateways and microservices disagreeing on who is authenticated. CDNs caching data the origin server meant to keep private.

Security research gets much simpler when you change how you read it. Stop asking "how do I hack X?" and start asking, "where does System A disagree with System B?" That's the lens I'm using here to break down the latest research and conference talks.
